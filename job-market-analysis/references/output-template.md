# Output Template — structure of `{Prefix}_Job_Market_Analysis_{Month}{Year}.md`

The output file has TWO layers:
- **Quantitative layer** (auto-generated by `aggregate.py`): the numbers.
- **Qualitative layer** (written by Claude): Tier 1/2/3 curation,
  positioning, sequencing.

⚠️ **CONTRACT WITH `search-jobs` — DO NOT BREAK.** Step 0c of `search-jobs`
parses this file to extract: (1) the target city, (2) the **Tier 1 table
(Title + Company)**, (3) market context (language, visa, sectors). The
**"Tier 1 — Priority Roles"** section must therefore stay in table format
with at minimum the columns `Role | Company | Level | Notes`. Everything
else can evolve freely.

## Tiering rule (how to classify a real posting into Tier 1/2/3)

1. Start from the **family's default tier** (`role-taxonomy.md`'s Tier
   column).
2. Adjust based on the **detected seniority**:
   - A Tier-3 family posting labeled `graduate`/`associate` -> move up to a
     **direct Tier-1 target** (rare, worth highlighting).
   - Any Tier-1 family posting in the `senior` bucket (5+ years) -> keep
     Tier 1 but annotate **"stretch / Mid-Senior"**.
3. Drop (don't list) if: `family == EXCLUDED`, OR `local_language_required`
   on a high-severity-language market (and that language isn't one you
   speak), OR the posting explicitly excludes visa sponsorship (and
   sponsorship applies to you).

## What Claude should (and shouldn't) do

- **Do**: fill the auto sections with `aggregate.py`'s output as-is; for
  the qualitative layer, only cite postings/companies that are actually
  present in the scraped dataset.
- **Don't**: invent a posting, a company, or a level. If the scrape returns
  nothing for a family, write that honestly ("no active Tier-1 postings
  detected for X at scrape time").
